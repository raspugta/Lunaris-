# LUNARIS
### Lunar Uncharted Navigation, Autonomy & Resource Intelligence System

**From lunar data to explainable exploration decisions.**

A decision-support workspace for Permanently Shadowed Regions (PSRs) near the lunar south pole.
It ingests real NASA data products (LRO LOLA elevation and PSR maps, LROC NAC imagery, Diviner
thermal-model products), builds terrain and hazard layers, ranks locations for *further
investigation*, plans an explainable A* rover route, and exports a provenance-aware mission brief.

> **Not a mission certification. Not proof of water ice.** Every layer is labelled
> *measured*, *derived*, *model estimate*, *illustrative* or *synthetic*. Unknown data is
> never treated as safe. Monocular depth is labelled *relative depth* unless calibrated.

Demo narrative: **Inspect → Understand → Prioritise → Navigate → Report.**

## Quick start (Linux, Python 3.12+; tested on 3.14)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/make_demo_fixture.py      # small SYNTHETIC fixture (offline)
.venv/bin/python -m pytest                          # 71 tests, no network or GPU needed
.venv/bin/python -m uvicorn backend.app:app --port 8000
```

Open <http://localhost:8000> for the landing page, and press **Launch mission console** (or go straight to
<http://localhost:8000/app>). In the console, choose a dataset and press **Load**.

Optional, for the Depth Anything V2 module (CPU build; ~200 MB, plus ~100 MB model weights
on first run, after which it works offline):

```bash
.venv/bin/pip install -r requirements-ml.txt
```

## Web demo (Vercel, free)

`site/` is a fully static build of LUNARIS, generated by the real pipeline:

```bash
.venv/bin/python scripts/export_static.py
```

It contains the landing page and the console for every dataset and crater. The console shows:

* every NASA layer, the suggested A* route, and rover simulations (VIPER, Perseverance-class, Pragyan) on nominal soil
* PDF/JSON reports and the 3D views
* Alvik `main.py` generation, done in the browser

Custom routes, re-weighting, the depth model and USB upload need the full backend, and the demo says so when you try them.

**Deploy:** import this repository at <https://vercel.com/new>. `vercel.json` already sets the output directory to `site/` with
no build step, so keep the defaults and press **Deploy**. Every `git push` to `main` redeploys automatically.

## Data setup (real NASA data)

Raw inputs live in `data/raw/` (immutable, git-ignored); derived products go to
`data/processed/`. All URLs below were verified against the producer's archive.

| Step | Command | Size | Source |
|---|---|---|---|
| LOLA DEM, DEM error, effective resolution, slope, PSR map, co-registered LROC NAC image for a 32 km Shackleton window | `python scripts/fetch_pgda_aoi.py --aoi shackleton` | ~50 MB (windowed HTTP range reads of cloud-optimised GeoTIFFs) | NASA GSFC PGDA product 90, Barker et al. 2023 — <https://pgda.gsfc.nasa.gov/products/90> |
| Diviner Polar Resource Product (south) | `curl -o data/raw/diviner/dlre_prp_south.tab https://pds-geosciences.wustl.edu/lro/urn-nasa-pds-lro_diviner_derived1/data_derived_prp/dlre_prp_south.tab` (+ `.xml`, `.lbl` from the same folder) | 605 MB | NASA PDS Geosciences Node, LRO-L-DLRE-5-PRP-V2.0 |
| Resample Diviner PRP onto the AOI grid | `python scripts/rasterize_diviner_prp.py --aoi shackleton` | — | documented nearest-facet method |
| Average sun and Earth visibility (for the rover simulation) | download `AVGVISIB_85S_060M_201608.TIF` (PGDA) plus both `.LBL` files (imbrium.mit.edu) into `data/raw/illumination/`, then `python scripts/fetch_illumination_aoi.py` (fetches the Earth map rows by HTTP range) | 34 MB + ~5 MB | Mazarico et al. 2011, PGDA product 69 |
| **Crater library** (Shoemaker, Haworth, Faustini, de Gerlache, Sverdrup, Slater, Cabeus, Nobile, Amundsen) | `python scripts/fetch_crater.py --all` (or `--crater crater_cabeus`). It needs the Diviner table and illumination files above for the thermal/sun layers | ~10–20 MB per crater | Windows centred on IAU/USGS Gazetteer positions; PGDA LOLA at 20/40/80 m chosen by crater size |
| *(optional)* Full PDS LOLA GDR 87.5°S, 20 m | `curl -O https://pds-geosciences.wustl.edu/lro/lro-l-lola-3-rdr-v1/lrolol_1xxx/data/lola_gdr/polar/img/ldem_875s_20m.img` (+ `.lbl`) into `data/raw/lola/` | 115 MB | NASA PDS, LRO-L-LOLA-4-GDR-V1.0 |

Each fetch writes checksums and a provenance record (`fetch_record.json`, `prp_record.json`).
The dataset registry is `configs/datasets.yaml`. Every layer's source, product ID, instrument,
units, processing level and licence is declared there and shown in the UI. Missing fields are
flagged, never invented.

If a file is missing, the app still runs and shows that layer as **not ingested**, with the
command that fetches it.

## What it does

| Module | Implementation | Key semantics |
|---|---|---|
| A. Ingestion & provenance | `core/ingestion/` — GeoTIFF, PDS3 IMG+LBL (own ODL parser), PNG/JPEG | SHA-256, CRS, pixel size, no-data, missing-metadata list, actionable errors |
| B. Reconstruction | `core/reconstruction/` — Depth Anything V2 adapter (lazy, GPU/CPU, disk cache) + LOLA comparison | Output = *relative depth, unitless*; metric errors only out-of-sample after an explicitly labelled affine fit |
| C. Terrain & hazards | `core/geospatial/terrain.py` — Horn slope, plane-detrended RMS roughness, hazard classes | Slope only from calibrated DEMs; NaN propagates; unknown is its own class |
| D. Ice investigation priority | `core/ice_priority/evidence.py` — weighted evidence over PSR, Diviner T<sub>max</sub>, ice-stability depth | Requires thermal evidence; "not assessed" otherwise; per-cell breakdown; ±50 % sensitivity |
| E. Navigation | `core/navigation/` — cost surface + 8-neighbour A* (octile, admissible) | No-data blocked, uncertainty penalised, no corner-cutting; alternatives explained |
| F. Dashboard | `frontend/` — vanilla JS + vendored three.js r160 (works offline) | Layer status chips, legends, provenance, 2D + 3D, inspector, loading/error states |
| G. Reports | `core/reporting/` — strict JSON + PDF (ReportLab) | Disclaimer, legends, scale bar only when calibrated, orientation, attribution |
| Landing page | `frontend/landing.*`: three.js NASA CGI Moon Kit (LROC colour + LOLA-derived normal map), GSAP scroll choreography | Everything vendored locally (fonts, GSAP, three.js), so it works offline |
| H. Rover simulation | `core/rover/` + `frontend/sim.js` — NASA VIPER (published specs) driven over the route: attitude, Bekker–Wong slip/sinkage, tip-over, PSR time limit, energy | Every parameter tagged published / derived / assumed; verdict PASS / MARGINAL / FAIL plus loose-soil sensitivity. ## Crater library

Open it with **◎ Craters** in the console top bar (or the gallery shown before any dataset is loaded). Each card shows:

* a LOLA shaded-relief thumbnail, with permanently shadowed ground tinted blue
* the IAU gazetteer diameter and position
* the *measured* PSR fraction of the window
* which NASA layers are present

Click a card to load it. Crater definitions live in `configs/craters.yaml`; positions come from the IAU/USGS
Gazetteer subset in `configs/gazetteer_south80.json`. Named features shown on the map (dashed outlines with labels) and
each dataset's "features covered" list are **computed** from the gazetteer. A feature is listed only if its centre lies inside the
window, and it is marked *partial* when its rim extends outside. The original 32 km Shackleton window, for example, clips
Shackleton's rim by ~0.9 km.

Resolution per crater: 20 m for windows ≤ 40 km, 40 m ≤ 80 km, 80 m above that (PGDA publishes all three). The PSR map is
published only at 20 m, so it is averaged to the window resolution and becomes a PSR *fraction*. Craters near 85°S
(Cabeus, Amundsen) lie partly outside the 85°S illumination product; those cells are *unknown*, not dark.

## Arduino Alvik replay (4 ft × 4 ft floor grid)

**⬢ Send to Alvik** in the console shrinks the planned route into a 4 ft square. It generates a MicroPython `main.py`
(`rotate()` / `move()` steps, LED colours mirroring the simulation) and uploads it over USB with `mpremote`. Press ✓ on the
robot to run it. See [docs/ALVIK.md](docs/ALVIK.md).

## Visual assets (all NASA, credited in the UI)

* Moon globe: NASA Scientific Visualization Studio CGI Moon Kit (svs.gsfc.nasa.gov/4720): `lroc_color_poles_4k`, with a normal map computed from `ldem_16_uint`.
* Rover: NASA 3D Resources `Mars 2020 Perseverance Rover.glb` (to scale; measured wheel diameter 0.525 m = published 52.5 cm). VIPER is a procedural model built to NASA's published dimensions, because no official VIPER 3D file is released.
* Earth in the simulation sky: NASA Visible Earth Blue Marble.
* Illustrative-only elements, labelled in the UI: sun azimuth (date not modelled), regolith micro-texture (no effect on heights or physics), and the faint fill light.

## Configuration

`configs/default.yaml` holds every threshold and weight. Hazard thresholds (blocked at 25° slope
or 6 m RMS roughness) are **prototype assumptions** informed by public rover figures, not a
certified specification. Derived results are cached by a hash of (input checksums, config), and
that hash is printed in the UI and in every report.

## Limitations (summary)

* At 40 m/px analysis resolution, rover-scale hazards (boulders, small craters) are invisible. The
  app says so and does not run a boulder "detector".
* The PSR map, Diviner temperatures and ice-stability depth are *model products*, each with its own
  epoch and resolution. LEND hydrogen is deliberately not used per pixel.
* Depth Anything V2 is trained on terrestrial imagery. On polar NAC images its output correlates
  with LOLA (see validation), but an affine calibration does not transfer across the scene. It must
  not be used as topography.
* Routes ignore illumination, communications line-of-sight and thermal survival.
